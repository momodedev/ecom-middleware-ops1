**Ready-to-run test runbook (Kafka 2.3.2 A/B on Azure V5+CentOS7.9 vs V6+Rocky9.7)**

Assumptions:
1. Control node Terraform in manage_node is already working in your environment.
2. You have a CentOS-compatible test branch or patch applied for broker image/bootstrap compatibility in the Kafka Terraform path.
3. Both lanes use Java 11 and Kafka 2.3.2.
4. You run local steps in Windows PowerShell, and remote steps on the Linux control node shell.

---

**Phase 0: Define test constants**

Use these constants for both lanes:
1. Broker count: 3
2. Topic partitions: 24
3. Replication factor: 3
4. Min ISR: 2
5. Message sizes: 100B, 1KB, 10KB
6. Compression: none, snappy, lz4
7. Producer duration per case: 600s
8. Same region, same VNet policy, same disk size and caching mode

**Phase 6: Baseline system tests per lane (CPU, disk, network)**

Run on each lane separately (from control node against each broker or directly on broker SSH).

CPU baseline:

    sysbench cpu --threads=8 --time=120 run | tee ~/perf-results/LANE/cpu.txt

Disk baseline on broker (example via SSH):

    ssh rockyadmin@BROKER_IP "sudo fio --name=seqwrite --filename=/data/kafka/fio.test --size=4G --bs=128k --rw=write --iodepth=16 --direct=1 --numjobs=1 --runtime=120 --time_based --group_reporting" | tee ~/perf-results/LANE/fio-seqwrite.txt

Network baseline (iperf3, one broker server and one client):

    ssh rockyadmin@BROKER1_IP "pkill -f iperf3 || true; nohup iperf3 -s > /tmp/iperf3-server.log 2>&1 &"
    ssh rockyadmin@BROKER2_IP "iperf3 -c BROKER1_IP -t 60 -P 4" | tee ~/perf-results/LANE/iperf3.txt

---

**Phase 7: Kafka workload tests per lane**

Create topic once per lane:

    /opt/kafka/bin/kafka-topics.sh --bootstrap-server BROKER1_IP:9092 --create --if-not-exists --topic perf-topic --partitions 24 --replication-factor 3

Producer test matrix loop:

    for SIZE in 100 1024 10240; do
      for COMP in none snappy lz4; do
        /opt/kafka/bin/kafka-producer-perf-test.sh \
          --topic perf-topic \
          --num-records 5000000 \
          --record-size ${SIZE} \
          --throughput -1 \
          --producer-props bootstrap.servers=BROKER1_IP:9092 acks=all linger.ms=10 batch.size=65536 compression.type=${COMP} \
          --print-metrics \
          --time 600 \
          | tee ~/perf-results/LANE/producer-size${SIZE}-comp${COMP}.txt
      done
    done

Consumer test:

    /opt/kafka/bin/kafka-consumer-perf-test.sh \
      --bootstrap-server BROKER1_IP:9092 \
      --topic perf-topic \
      --messages 5000000 \
      --threads 4 \
      | tee ~/perf-results/LANE/consumer.txt

---

**Phase 8: Failure/recovery test per lane**

Under producer load, stop one broker and observe recovery:

    ssh rockyadmin@BROKER3_IP "sudo systemctl stop kafka"
    date | tee -a ~/perf-results/LANE/failure-recovery.txt
    /opt/kafka/bin/kafka-topics.sh --bootstrap-server BROKER1_IP:9092 --describe --topic perf-topic | tee -a ~/perf-results/LANE/failure-recovery.txt
    sleep 120
    ssh rockyadmin@BROKER3_IP "sudo systemctl start kafka"
    sleep 120
    /opt/kafka/bin/kafka-topics.sh --bootstrap-server BROKER1_IP:9092 --describe --topic perf-topic | tee -a ~/perf-results/LANE/failure-recovery.txt
